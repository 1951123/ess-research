# Forest10 ETL boundary v1

Issue #15 adds a small, dependency-free Forest10 vertical slice. It is a
benchmark-input boundary, not an optimizer, PostgreSQL integration, or
cardinality-estimation result.

## Explicit input contract

For real-data commands, use explicit `--data-root` if provided; otherwise use
`ESS_DATA_ROOT`, a researcher-approved persistent data-root environment
variable. If neither is set, fail closed rather than searching conventional or
historical paths. The path alone never bypasses file identity verification.
Under the resolved root the validator expects:

```text
<root>/arecel/incoming/arecel-data.tar.gz
<root>/arecel/audit-v1/audit.json
<root>/arecel/audit-v1/forest10.canonical.jsonl.gz
<root>/arecel/raw/data/forest10/original.csv
<root>/arecel/raw/data/forest10/workload/base.pkl
<root>/arecel/raw/data/forest10/workload/base-original-label.pkl
```

The validator accepts either the new normalized audit-v1 layout or the
source-pinned historical adapter layout (`archive_expected_sha256`,
`upstream.AreCELearnedYet`, and `datasets.forest10.{csv,pickles}`). Both are
normalized to the same pinned AreCEL commit, archive/hash, Forest10 row count,
schema-contract ID, pickle hashes, and canonical-workload hash. An incomplete
or mismatched audit is rejected; the historical layout is not accepted merely
because it has a familiar filename.

The canonical JSONL.gz is a separately supplied, derived audit artifact. It
must be produced by a separately authorized conversion from the hash-checked
workload/label inputs (or supplied by an independent audit), and is never
regenerated by this parser or obtained by deserializing pickle data. The
archive is inspected without extraction: unsafe member paths and missing
required members are rejected. The CSV is checked for exact header order, row
width, parseable finite double values or empty NULL fields, row count, and
SHA256.

The two pickle files are treated as opaque bytes. The module hashes them but
never imports or deserializes them. The accepted workload input is the
independently produced, hash-checked canonical JSONL.gz artifact.

## Output contract

`build` produces three deterministic JSON artifacts in a new, non-overwritten
output directory:

- `workload.json` (`cardinality-workload-v1`) contains stable task IDs,
  source IDs, source SQL, adapted estimator SQL, source-query hashes, split,
  source order, and weights. It contains no truth cardinality.
- `truth.json` (`cardinality-truth-v1`) contains the exact nonnegative integer
  cardinality, the original COUNT SQL, source-label provenance, and the same
  source/task identities.
- `manifest.json` (`arecel-forest10-etl-manifest-v1`) binds the schema/CSV
  identity, source and producer hashes, transformation version, split and
  output hashes.

The source truth SQL and the adapted planner-estimation SQL are intentionally
distinct. Adaptation is restricted to `COUNT(*)` → `SELECT *`, the audited
`forest10_original` → `public.forest10` relation, and quoted source-column
identifiers → lowercase catalog identifiers. Literals, predicate values,
operators, and predicate order are not rewritten. Unsupported relations or
quoted identifiers fail closed.

The generated artifacts preserve source order and use IDs of the form
`arecel_forest10_<split>_<index>`. The general AreCEL workload is not silently
declared eligible for the pairwise maximal-matching study; later analysis must
apply its own structural query-scope validator.

## Authorized derived canonical conversion

The regular parser and CI never deserialize pickle inputs. Issue #17 contains
a narrow researcher authorization for a one-time conversion of only the two
verified Forest10 pickle hashes. The gated converter is
`experiments/arecel/convert_verified_pickle.py`; it requires
`--allow-pinned-pickle-conversion`, checks the exact workload and label SHA256
values before loading, uses a restricted class allowlist, and refuses an
existing output. It is intended for a disposable network-disabled process
with read-only approved inputs and a temporary writable output. The resulting
`arecel-forest10-derived-canonical-v1` artifact has its own SHA256 and must
retain the historical canonical SHA256 as a reference; the two hashes must
never be conflated.

The derived contract records 10,000 valid and 10,000 test records, source
order, stable IDs, source SQL and its hash, exact nonnegative truth, finite
source selectivity, and an explicit unit-weight policy because the source
pickles contain no task weights. This conversion is an acquisition exception,
not a relaxation of the normal ETL trust boundary or an invitation to load
arbitrary pickle files.

The pinned `Query` objects do not contain raw SQL strings. At the pinned
upstream commit, `query_2_sql(..., aggregate=True, split=False, dbms='postgres')`
iterates the ordered predicate mapping, emits `[]` as one parenthesized
`BETWEEN` predicate, and leaves the other operators and values unchanged. The
derived v1 renderer deliberately adapts this to the ETL source contract by
adding `public.` qualification, quoting source identifiers, omitting redundant
`BETWEEN` parentheses, and adding a semicolon. Consequently, canonical records
preserve predicate values, operators, and order but do not claim byte-for-byte
preservation of unavailable original SQL.

## Commands

From the repository root:

```sh
export ESS_DATA_ROOT=/absolute/path/to/persistent/research-data
PYTHONPATH=src .venv/bin/python -m ess_research.arecel.forest10 inspect \
  --data-root "$ESS_DATA_ROOT"

PYTHONPATH=src .venv/bin/python -m ess_research.arecel.forest10 build \
  --data-root "$ESS_DATA_ROOT" \
  --output-dir "$ESS_DATA_ROOT/etl-output/forest10-test-v1" \
  --split test
```

`inspect` returns exit status 2 with `BLOCKED_MISSING_INPUT` when the declared
root is incomplete. `build` writes only below `<data-root>/etl-output/` or
`<data-root>/experiment-data/` and refuses to overwrite an existing output
directory.
There is no download command in this PR: acquisition must be a separately
authorized, pinned, hash-checked and license-reviewed action.

## Shared data / isolated experiment execution

The verified archive, CSV, pinned pickles and canonical audit are **immutable
read-only inputs** under `ESS_DATA_ROOT`; they may be reused across Issues
without downloading again. Never regenerate them in place or confuse the
historical and derived canonical hashes. Sharing inputs does **not** mean
sharing a PostgreSQL database, `PGDATA`, statistics objects, sample replay
file, `ANALYZE` state, scratch outputs, or Python environment.

Use a separate `ESS_ISSUE_ROOT` and a separate PostgreSQL cluster, socket,
port, logs and disposable database for **each Issue**. Import the frozen
Forest10 source into that Issue's own PG instance. Keep temporary calibration,
fixed samples and mutable results under the Issue root. Use a separate
`.venv` per Git Worktree, with pinned dependencies and reproducible commands.
See [Git Worktree + Codex workflow](git-worktree-workflow.md) for the complete
runtime-isolation and cleanup policy.

The actual archive and canonical assets must still pass strict SHA-256 and
manifest checks, including when the root is supplied through the environment.
Neither an unset data root nor missing data should trigger implicit downloads,
searches of old machine paths, or fallback to synthetic experiment results.
