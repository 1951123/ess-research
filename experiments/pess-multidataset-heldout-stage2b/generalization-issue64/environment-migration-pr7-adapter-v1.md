## Structured EXPLAIN adapter

`PR7StructuredExplainAdapter` issues opt-in `EXPLAIN (ESS_DIAGNOSTICS, FORMAT JSON, SUMMARY OFF)` through the pinned `psql` helper and delegates to `parse_pr7_structured_explain`. It fails closed unless there is exactly one query record, a `complete` diagnostics status, matching event count and ordered sequence, exactly one `base_estimate` for the fresh relation OID, and a finite positive `nrows_preclamp`. It never substitutes Plan Rows for the pre-clamp value.

If MCV events are present, each two-key selection must map to the current catalog OID/candidate ledger and have matching relation/stat OIDs, unique claimed clause indexes, and one finite numeric estimate whose `clause_count` matches those clause records. When there are no MCV events, the adapter returns `NO_MCV_EVENTS` rather than asserting physical coverage. This distinction matters because the prior Forest10 fixed-sample pilot did not establish a usable MCV payload for its tested pair. The existing PR #58 server-log trace adapter remains unchanged and available as an independent comparison path. Neither adapter is invoked here.
