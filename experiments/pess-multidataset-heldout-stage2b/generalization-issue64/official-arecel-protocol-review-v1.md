## Outcome-free assessment

**Source-derived:** Issue #67 / PR #68 adds `prepare_valid_workload()`, which reads only the pinned workload pickle, emits the official valid workload with stable `arecel:{dataset}:valid:{source_index}` IDs and source SQL, and never opens the label pickle. Its reviewed discovery reports 45/78/55/21 positive-support pairs across Forest10/Census13/DMV11/Power7, based on all 10,000 official valid queries per dataset. The selection universe is every such pair, ordered by source schema order; none is claimed to be used or beneficial in PostgreSQL. No candidate is top-K filtered. The broader static restriction contract is not expanded into a claim beyond Issue #47's narrower equality-only physical evidence.

The existing PR #58 task/model representation can carry an arbitrary list of query tasks and candidate pairs, but its resource chooser cannot: `choose_model_sets()` iterates `range(1 << candidate_count)`. At 78 candidates this is `2^78` masks per budget. Do not invoke it or silently cap candidates; selecting all pairs requires a separately reviewed exact, tractable optimizer before calibration can start.

The current path is not execution-ready:

1. PR #68 solves workload-only candidate discovery, not valid-truth access. Calibration needs valid cardinality truth, while legacy `archive.prepare()` unpickles one all-split label pickle and writes every truth split. Establish a valid-only truth route that does not expose test labels before selection; otherwise stop at this firewall.
2. **Calibration query-count decision:** use all 10,000 official valid tasks per dataset, avoiding a separately sampled-valid estimand. Measure Empty once per task and a candidate singleton only when that pair is statically available for the task; the model's loss intersects selected resources with the task's available-edge set, so other `b` values cannot affect the objective. Freeze the exact candidate-task count from the discovery support counts before calibration. This is a design decision, not an executed measurement. A count-only CLI attempt failed during workload-only pickle deserialization because system Python lacks NumPy and produced no candidate results; the label pickle was not opened, and no environment was installed or borrowed. Thus only the conservative upper bound is recorded here.
3. A conservative calibration ceiling assumes every candidate is available on every valid task: 2,030,000 plans (460k / 790k / 560k / 220k by dataset); the exact plan is lower and determined outcome-free from the support counts. Full test evaluation adds at most 280,000 (70k per dataset: shared Empty plus at most two distinct selected sets at each nonzero budget). Overall ceiling: **2,310,000** (530k / 860k / 630k / 290k per dataset). This is a deterministic upper bound, not a runtime estimate. The test phase alone exceeds the old 1,800-held-out-query cap; a new total plan cap and researcher-approved runtime/disk limits are required.
4. PR #58 currently uses small frozen cohorts, positive pre-clamp trace estimates, requires every candidate singleton for every task, and does not record Plan Rows Q1. Reuse only the corrected-log/model/matching definitions after pin verification; adapt full valid/test iteration, eligible-edge-only calibration records, and Q1 Plan Rows analysis. Add focused synthetic tests for that adapter. A targeted PG trace remains optional unless claiming which statistic PostgreSQL selected.
5. The current exact resource chooser's `2^n` search is intractable at the largest reviewed universe (`n=78`). Identify and validate an exact tractable optimizer for the frozen objective before calibration; no top-K candidate truncation or unapproved approximate method is proposed.

The test set contains previously exposed Issue #48 identities for Forest10/Census13. Keep them in the official test evaluation, identify them from frozen identity-only protocols, and report an exposed/unexposed identity stratum. Because Issue #59 documents train/valid/test template overlap, do not present the unexposed subset or the full split as an untouched confirmation or unseen-template result. Do not use prior test metrics to choose resources, queries, or parameters.
